# Overlay Selection Performance — Test Checklist

**Ветка:** `fix/overlay-selection-perf`
**Версия:** 0.9.2

---

## Шаг 0. Проверка что патч применён правильно

1. Открыть `overlay.js`, найти строки в начале файла:
```js
let localDragging = false;
let localStart = { x: 0, y: 0 };
let localCurrent = { x: 0, y: 0 };
```
Если их нет — патч не применён, дальше не идти.

2. Найти функцию `renderSelection` — должна использовать `selection.style.transform`, НЕ `selection.style.left`/`top`.

3. В `overlay.css` найти блок `#selection` — должна быть строка `transform: translate(0px, 0px);`. Если там всё ещё `left/top` без transform — CSS-часть патча не применена.

4. Перезапустить Electron полностью (не hot-reload):
```
taskkill /F /IM electron.exe
```
(или закрыть через трей → Quit), затем запустить заново. Overlay-окна кешируют старый JS при hot-reload — без полного рестарта тесты дадут ложный результат.

## Тесты

### Тест 1 — Базовая плавность на одном мониторе
1. Alt+Space.
2. Медленно провести мышью по диагонали экрана (левый верх → правый низ), не отпуская кнопку.
3. **Ожидаемый результат:** рамка визуально "приклеена" к курсору, нет видимого лага (>1 кадра отставания на глаз).
4. **Как распознать провал:** рамка "прыгает" рывками или заметно отстаёт от курсора на 50-100мс.

### Тест 2 — Замер FPS через DevTools
1. В `main.js`, внутри `win.webContents.once('did-finish-load', ...)` в функции `showOverlayWindows`, временно добавить:
```js
win.webContents.openDevTools({ mode: 'detach' });
```
2. Перезапустить приложение, Alt+Space.
3. В открывшемся DevTools → вкладка **Performance** → кнопка record (●).
4. Провести drag выделения 2-3 секунды.
5. Остановить запись.
6. В секции **Frames** посмотреть на зелёные полоски — должны быть ровные ~16.6ms (60fps). Красные/жёлтые пометки = long tasks.
7. **Ожидаемый результат:** нет long tasks >50ms во время drag, FPS не проседает ниже ~50.
8. **Обязательно убрать** `openDevTools` из main.js перед коммитом/использованием — это не должно уйти в билд.

### Тест 3 — Cross-monitor drag (если 2+ монитора)
1. Alt+Space.
2. Начать mousedown на мониторе A, вести курсор через границу на монитор B, не отпуская кнопку.
3. **Ожидаемый результат:** рамка продолжает расти непрерывно, пересекая границу без "заморозки" в момент перехода.
4. Отпустить кнопку на мониторе B.
5. **Ожидаемый результат:** ask-bar появляется на мониторе B (там, где отпущена кнопка), а не на A.
6. **Как распознать провал:** рамка замирает на границе экрана А и не растёт дальше, пока курсор на Б.

### Тест 4 — Обратный cross-monitor (B → A)
Повторить тест 3 в обратном направлении. Асимметрии быть не должно (проверяет что `e.buttons & 1` работает одинаково в обе стороны).

### Тест 5 — Многомониторный сетап 3+ экранов (если есть)
1. Начать drag на среднем мониторе, провести через оба соседних до самых краёв.
2. **Ожидаемый результат:** рамка непрерывна на всех трёх, ask-bar появляется там, где реально отпущена кнопка (не на промежуточном мониторе).

### Тест 6 — Разный DPI/scaleFactor между мониторами
1. Проверить `scaleFactor` каждого монитора: DevTools console (обычный, не overlay) → `require('electron').screen.getAllDisplays().map(d => d.scaleFactor)` (если доступен nodeIntegration в каком-то окне) либо через Windows: Настройки → Экран → масштаб.
2. Если мониторы разные (напр. 100% и 150%) — повторить тест 3.
3. **Ожидаемый результат:** размер рамки в px-label (`dimLabel`) не "скачет" при пересечении границы между DPI-зонами.

### Тест 7 — Быстрый клик без drag (rapid click)
1. Alt+Space.
2. Кликнуть мышью (mousedown+mouseup) без движения, максимально быстро.
3. **Ожидаемый результат:** нет краша, нет зависшего состояния (`localDragging` не остаётся `true` — проверить через добавленный временно `console.log(localDragging)` в конце `mouseup`-хендлера).
4. Overlay должен остаться открытым (ask-bar не появляется, т.к. rect < 10px по логике `onSelectionDone`).

### Тест 8 — Мелкое выделение (<10px)
1. Alt+Space, выделить рамку размером ~5×5px.
2. Отпустить.
3. **Ожидаемый результат:** `lastRect = null`, ask-bar НЕ появляется (регрессия из старой логики не должна была затронуться патчем).

### Тест 9 — Preset quick hotkey (обход ask-bar)
1. Настроить quick hotkey с преднастроенным промптом (через настройки приложения).
2. Вызвать этот hotkey, выделить область.
3. **Ожидаемый результат:** запрос уходит сразу в `captureRegion` с preset-промптом, ask-bar НЕ появляется. (Патч не должен был это сломать — проверяем регрессию.)

### Тест 10 — Voice input
1. Обычное выделение (без preset hotkey) → появляется ask-bar.
2. Нажать 🎤.
3. Сказать что-то вслух.
4. **Ожидаемый результат:** текст появляется в `ask-input`, `mic-btn` подсвечивается активным на время записи.

### Тест 11 — Esc отмена во время drag
1. Alt+Space.
2. Начать drag (mousedown + немного подвигать), не отпуская.
3. Нажать Esc, не отпуская кнопку мыши.
4. **Ожидаемый результат:** overlay закрывается (`closeAllOverlays()`), приложение не виснет, `captureInProgress` сбрасывается в `false` (проверить — повторный Alt+Space должен снова открыть overlay).

### Тест 12 — Множественные циклы открытия/закрытия (утечка памяти/окон)
1. Повторить Alt+Space → Esc **20 раз подряд**.
2. После последнего цикла — Диспетчер задач (Windows) → найти процессы `electron.exe`, посчитать количество.
3. **Ожидаемый результат:** количество процессов стабильно (не растёт линейно с числом циклов). Всплеск RAM после 20 циклов — не более чем в 1.5-2 раза от исходного.

### Тест 13 — Ask-bar submit после нормального drag
1. Обычное выделение (не preset).
2. В ask-bar ввести текст, нажать Enter или "Ask →".
3. **Ожидаемый результат:** `captureRegion(lastRect, text)` уходит, overlay закрывается, открывается chat/quick-ask панель с ответом.

### Тест 14 — Параллельная работа два overlay подряд без рестарта
1. Alt+Space → выделить → дождаться quick-ask панели → Esc/закрыть панель.
2. Сразу Alt+Space снова → выделить на **другом** мониторе (если есть) или том же.
3. **Ожидаемый результат:** второй overlay работает так же плавно, как первый — нет деградации от "залипшего" состояния между вызовами (`localDragging`, `rafPending`, `pendingEvent` должны сбрасываться корректно между сессиями — проверяет что нет утечки state между `onOverlayInit` вызовами).

## Условия/исключения

- Тесты 5, 6 — только если физически доступно железо/виртуалка с нужным количеством мониторов или разным DPI. Без этого — не проверяемо, помечать N/A, не придумывать результат.
- Тест 2 требует ручного отката `openDevTools()` — если забыть, в проде у пользователей будет вылетать DevTools при каждом Alt+Space.
- Если хоть один тест из 1, 3, 4, 7, 11, 12 — Fail, патч не мержить, откатывать ветку.
- Тесты 9, 10, 13 — регрессионные, проверяют что патч не сломал несвязанный функционал. Если падают — смотреть diff внимательнее, скорее всего задет не тот участок кода.
